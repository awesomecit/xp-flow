# Diario dev personale

Stessa convenzione del repo `agile` di lavoro: **un file per recap**, nominato
`YYYY-MM-DD-tema.md`, append-only, **mai fonte di verità** — i *perché* stanno in
ADR/DECISIONI dei repo, i *cosa* nel git log, il flusso nell'event log di xp-flow.

Cosa finisce qui (generato dai comandi, non scritto a mano):
- `YYYY-MM-DD-stato[-deep].md` — recap di `/stato`
- `YYYY-MM-DD-standup.md` — cerimonia `/standup`
- `YYYY-MM-DD-sprint.md` — chiusura sessioni di sprint
- `YYYY-WW-retro.md` — retrospettive (copia canonica in `docs/retro/` di xp-flow)
- `YYYY-MM-DD-<tema>.md` — sessioni di setup/discovery fuori cerimonia

Una entry che duplica ADR, git log o board è rumore: solo contesto, svolte,
vicoli ciechi e lezioni.
